# M4 TiDB（MySQL バックエンド検証）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Do **not** use subagents. One commit + one PR per task; merge to `main` before the next.
>
> **CI:** Every commit message AND every merge commit subject MUST include `[skip ci]`.
>
> Merge: `gh pr merge --merge --subject "Merge pull request #N from branch [skip ci]"`

**Goal:** 既存 `backend/mysql` を TiDB 上で適合テスト（と可能ならカオス）し、流用可否を確定する。SKIP LOCKED が使えなければ条件付き更新フォールバックを `backend/mysql` に足す。

**Architecture:** TiDB は MySQL プロトコル互換。DSN は `TASUKI_TIDB_DSN`（未設定時は skip）。コンテナは単一ノード `pingcap/tidb`（unistore）でローカル検証する。新規モジュールは作らず、mysql 実装を共有する（02-architecture の方針）。

**Tech Stack:** 既存 `backend/mysql`、Docker `pingcap/tidb`、`backendtest`、既存 chaos worker（`TASUKI_BACKEND=mysql` + TiDB DSN）。

**Spec:** [docs/04-plan.md](../../04-plan.md) M4 項目 2、[docs/02-architecture.md](../../02-architecture.md)
